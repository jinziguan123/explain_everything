# H1 盲评实验执行手册

> 依据: [设计预期-修正版](设计预期-修正版.md) §四 H1。
> 本实验优先于一切新功能开发; 出结果前冻结体验类迭代 (§九 Phase V)。

## 实验目的

检验核心假设 H1: **本系统的完整产出 (图 + 叙事报告) 优于同一模型的单次深度 prompt 产出。**
这是整个产品的存在性检验——若失败, 按 §〇 重写设计而非继续开发。

## 准备

1. **题库**: 编辑 [seeds/h1_questions.txt](../seeds/h1_questions.txt), 把示例题替换为你滩头领域的 10 个真实"为什么"问题。
2. **评委**: 招募 5 名符合滩头画像的人 (研究者/分析师/深度写作者), 互相独立。
3. **配置**: `.env` 配好 LLM (A/B 两组用同一模型, 这是公平性前提)。

## 执行

```bash
explain bench seeds/h1_questions.txt --out bench_results --budget 20 --seed 42
```

- 每题 A 组约需数分钟、几十次 LLM 调用; 10 题预计 0.5-2 小时, 中途单题失败不影响其余 (见 manifest.json)。
- 产出: `bench_results/qNN/X.md|Y.md` (盲评材料)、`评分表.md`、`manifest.json` (成本统计, 可看)、`.key.json`/`.answers.json` (**揭盲映射, 评分结束前任何人不得查看**)。

## 评分

每位评委独立完成 `评分表.md` 副本, 每题回答:

- **Q1**: 哪份更有助于你写出对外发布的分析? (X / Y / 平)
- **Q2**: 哪份包含你事先没想到的有效原因? (X / Y / 平)

规则: 不许讨论、不许查来源、不许用 AI 辅助判断; 每题先读完两份再作答。

## 结算与判定

1. 收齐 5 份评分表后, 用 `.answers.json` 揭盲, 把 X/Y 换算为 A/B。
2. 计票: 每题每评委 Q1、Q2 各一票, "平"记 0.5/0.5。A 组综合胜率 = A 得票 / 总票数。
3. 判定 (硬标准, 事先承诺, 不许事后挪线):

| A 组综合胜率 | 结论 | 动作 |
|---|---|---|
| ≤ 50% | **H1 失败** | 设计预期文档作废重写 (§〇); 停止当前 roadmap |
| 50% – 65% | 灰区 | 分析败因 (看 Q1/Q2 拆分与评语), 修订后**仅重测一次** |
| > 65% | **H1 通过** | 进入 Phase G (证据接地) |

4. 附加分析 (不影响判定, 写入实验记录): Q2 的 A 胜率单独看 (反直觉价值是差异化卖点); `manifest.json` 中 A/B 耗时比与 `counterintuitiveness` 分布; 评委间一致性。

## 诚实条款

- 不许为实验临时调 prompt 后只跑有利题目; 题库在跑实验前冻结。
- 失败题 (status=error) 如实报告, 不许悄悄剔除后宣称全样本。
- 实验记录 (原始评分表 + 揭盲结果 + 结论) 存入 `docs/h1-results/`, 无论结果如何。
