## 〇、本文档自身的失败条件

按本项目自己的哲学，理论必须可失败，设计文档也一样。出现以下任一情况，本文档作废，需要重写而非修补：

1. §四的核心假设实验（H1 盲评）完成后判定为失败；
2. 连续两个开发周期，团队发现自己在实现本文档未定义的概念（说明文档又开始靠隐喻驱动）；
3. 滩头用户（§二）以外的某类用户出现了显著更强的自发使用，说明 §二 的选择错了。

## 一、产品身份：单一选择

### 决策 1：本产品是"人的思考假体"，不是自主认识论引擎

旧文档在两个产品之间滑动：(a) 帮助人建立世界模型的工具（人在环中）；(b) 自主演化的认知系统（以摆脱人为目标）。两者用户不同、成功标准互斥，必须二选一。

**本文档选择 (a)。**

理由：
- (a) 有可触达的用户和可设计的验证实验；(b) 没有——"自主理论形成"在没有外部评判者时无法定义成功。
- 现有实现（HITL 审批、stage gate、chat 交互）实际上已经全部押在 (a) 上，承认现实。
- (b) 不被删除，降级为附录 A 的远景，**不承诺、不排期、不影响任何当前设计决策**。

推翻条件：若 (a) 的核心假设被证伪（§四 H1），且事后分析显示失败原因是"人在环成本"而非"解释质量"，则重新评估 (b)。

### 一句话定义

> **Explain Engine 是一个帮助知识工作者把"为什么"问题加工成有证据状态标注的因果结构、并让这些结构跨问题累积复用的思考工具。**

与 chatbot 的区别不靠声明，靠两个 chatbot 给不了的交付物：
1. **可检视的结构**：每个结论能追溯到它依赖的变量、边和证据；
2. **可累积的资产**：第 10 次提问比第 1 次便宜且深刻，因为变量库和理论在复用。

如果这两点不成立，本产品就该被一个好 prompt 取代——这正是 §四 要检验的。

## 二、用户与边界

### 决策 2：滩头用户是"在单一领域内反复提问的深度内容生产者"

具体画像：独立研究者、行业分析师、深度专栏作者、写论文的研究生。共同特征：

| 特征 | 为什么必要 |
|------|-----------|
| 在**同一个领域**反复问"为什么" | 跨 session 累积（lexicon/theory）只在领域内复用时产生价值，这是产品相对单次 LLM 问答的唯一结构性优势 |
| 产出物需要**对外承担正确性责任**（报告/文章/论文） | 只有这类人愿意为"证据状态标注"付出额外交互成本；纯好奇用户问一次 ChatGPT 就走了 |
| 已经在用 LLM，且被"流畅的伪深刻"坑过 | 痛点真实存在，不需要教育 |

理由：本产品的边际价值 = 结构 + 累积 + 证据标注，三者都只对"重复、严肃、单领域"的提问者成立。"解释一切"是反规格——系统架构保持领域无关，但**产品体验、示例、验证实验全部按单领域深耕设计**。

推翻条件：见 §〇 第 3 条。

### 明确不服务的场景（负边界）

- **一次性好奇提问**（"为什么天空是蓝的"）：单次 LLM 问答严格更优，不竞争。
- **私人心理问题**（"为什么我执行力差"）：需要私人上下文和心理学框架，证据接地机制无法工作。旧文档把它和宏观问题混为同一场景，是错误的。
- **实时事件追踪**：本产品的图谱以"机制"为单位演化，跟不上小时级新闻，也不必跟。

### 交互成本预算（定义）

| 指标 | 上限 | 测量方法 |
|------|------|---------|
| 首次价值时间（TTFV） | ≤ 3 分钟 | 从输入问题到看到第一版带结构的解释图 |
| 单 session 强制人工操作 | ≤ 2 次 | HITL 审批从"阻塞步骤"改为"可跳过的异步修订"，默认采纳 |
| 第 10 个 session 的变量复用率 | ≥ 20% | 新 session 图中来自 lexicon 复用的 L1/L2 节点占比 |

第三条是"累积价值"承诺的可测形式，低于阈值即 lexicon 假设失败（§四 H3）。

## 四、核心假设与证伪协议

本产品建立在三个可证伪的假设上。任何 roadmap 项目若不服务于验证或兑现这三个假设之一，不予排期。

### H1（解释质量）：本系统的产出优于单次深度 prompt

- **实验协议**：选取滩头领域内 10 个"为什么"问题。A 组 = 本系统完整流程产出（图 + 叙事报告）；B 组 = 同一底层模型、一个精心设计的深度分析 prompt、单次产出。5 名滩头画像用户盲评，每题回答两个问题："哪份更有助于你写出对外发布的分析？""哪份包含你事先没想到的有效原因？"
- **判定**：A 组综合胜率 ≤ 50% 即失败——打平即失败，因为 A 的成本是 B 的 5-10 倍。胜率 50%-65% 为灰区，分析败因后修订重测一次；> 65% 通过。
- **时限**：本实验优先于一切新功能开发。在 H1 有结果之前，冻结所有纯体验类迭代（详见 §九）。

### H2（证据接地的价值）：带证据标注的图比纯 LLM 内省的图更受信任且更准确

- **实验协议**：同一问题分别用"接地管线开/关"各跑一次，用户盲评信任度；另抽取 20 条"实证"级边人工核查来源真实性，来源伪造率 > 10% 则接地实现不合格。
- **判定**：信任度无显著差异 → 接地只保留为可选项，不做为核心卖点；伪造率超标 → 接地管线重做。

### H3（累积价值）：跨 session 复用让第 N 次提问产生递增价值

- **测量**：§二 交互成本预算第 3 条 + 用户访谈（"系统有没有用旧变量给过你新启发？"，要求举出具体实例）。
- **判定**：复用率 < 20% 或 5 名用户无一人能举出实例 → lexicon/theory 整层降级为内部缓存，不再作为产品卖点。

## 五、核心度量的操作化定义

旧文档的中心概念全部没有定义，本节逐个补齐。所有定义都是**代理指标（proxy）**，不冒充理论真值；选择标准是：可用现有代码计算、单调方向正确、能被博弈时容易被发现。

### 5.1 压缩值（Compression Value）

对解释图 G，设 P 为现象集（L0 节点），利用现有 simulation 引擎的一致性分：

```
覆盖 Cov(G) = Σ_{p∈P} consistency(p)          # 现有 check_consistency_batch 直接给出
描述长度 L(G) = |V_L1| + |V_L2| + 0.5·|E|      # 解释性结构的尺寸，L0 是输入不计入
压缩值 CV(G) = Cov(G) / L(G)
```

单个变量 v 的**洞察增益** = ΔCov / ΔL（加入 v 前后的压缩值边际变化）。这取代旧文档中不可计算的 `compression_gain`，并给 reflection 引擎的 prune 决策提供了统一依据：洞察增益持续为负的节点是修剪对象。

已知可博弈点：把多个机制塞进一个变量名可以压低 L。对策：变量准入要求机制描述单一性（已有 canonical mechanism 机制可复用），由 light LLM 审查打回复合变量。

### 5.2 反直觉性（Counterintuitiveness）

旧文档列为好解释五标准之一但从未定义。操作化：

```
1. bootstrap 阶段，在展示任何图之前，先让用户（或 light LLM 作为代理先验）列出 top-3 预期原因 → 先验集 Prior
2. 收敛后取图中中心度最高的 k=3 个 L1/L2 变量 → 核心集 Core
3. 反直觉度 CI = |Core \ Prior| / k   （语义匹配用现有 embedding，阈值沿用 0.85）
```

CI 本身不进优化目标（否则系统会学会故意标新立异），只作为**报告指标**呈现给用户："本次解释中有 2/3 的核心变量在你的预期之外。"

### 5.3 证据加权置信度

废除 `confidence = plausibility / 5.0`（LLM 给自己打分）。新定义：

```
confidence(edge) = base(epistemic_tier) × llm_plausibility
其中 base：实证=1.0，推断=0.7，假设=0.4（tier 定义见 §六.2）
```

即 LLM 的合理性评分只能在证据等级允许的天花板内浮动。无证据的边永远到不了高置信——这是"防伪深刻"从口号变成机制的关键一步。

### 5.4 收敛判据

保留现有"预算 + 一致性停滞"机制，但停止条件升级为以压缩值表达：

```
连续 W=3 个 tick 满足 ΔCV < ε（ε 默认 0.01）→ 收敛
```

这把旧哲学"新增关系不再提升解释力"从描述变成判据，且与 5.1 共用计算。

## 六、证据接地：从"输入层"升格为"地基"

### 决策 3：建图过程强制接地，证据状态是节点/边的一等属性

旧文档"搜索不是核心，只是输入层"是本设计最大的单点错误，予以推翻。对一个解释引擎，**证据是认识论地基**：压缩事实得到理论，压缩幻觉得到高置信的幻觉。

### 6.1 接地管线（协议）

```
bootstrap / expansion 产生候选节点或边（LLM 内省，不变）
    ↓
声明抽取：把候选改写为可检索的具体断言（light LLM）
    ↓
检索验证：web 搜索 ≥ 2 个独立来源（复用现有 chat/web_search.py，移入建图管线）
    ↓
判定：支持 → 实证；来源冲突 → 标记"争议"并保留两说；查无 → 维持"假设"级
    ↓
来源 URL + 摘要 落盘到节点/边的 evidence 字段
```

成本控制：不是每条边都检索。只对两类对象强制接地：(a) 全部 L0 现象（它们冒充"观察"，最不该是幻觉）；(b) 中心度 top-k 的 L1/L2 入边（核心结论所系）。其余对象保持"假设"级，由 5.3 的置信天花板压低其影响力。

### 6.2 证据状态机（定义）

旧文档的 Fact/Inference/Insight/Speculation 四层保留，但给出判定规则与 UI 后果：

| 等级 | 判定规则（可自动执行） | UI 后果 |
|------|----------------------|---------|
| 实证 Fact | evidence 字段含 ≥ 2 独立来源且无冲突 | 实线、饱和色，可点击查看来源 |
| 推断 Inference | 自身无直接证据，但其在图中的全部前驱为实证/推断 | 实线、中等饱和 |
| 假设 Hypothesis | LLM 提出、检索未支持也未否定 | 虚线、低饱和 |
| 争议 Contested | 检索到相互冲突的来源 | 双色边 + 角标，详情展示两说 |

状态可迁移（假设 + 新证据 → 实证），迁移历史落盘。**叙事层输出必须按等级分段措辞**："数据显示…（实证）/ 由此可推（推断）/ 一个未经验证的可能是…（假设）"——伪深刻的最后一道防线在文案层。

## 七、理论层：从挖掘到可证伪

### 7.1 理论的准入

保留 gSpan motif 挖掘作为候选来源，但 motif ≠ theory。候选要成为理论，必须满足：

1. 跨 ≥ 2 个 session 复现（现有逻辑保留）；
2. **登记至少一条可检验预测**（见 7.2）。登记不出预测的候选永久停留在"叙事模式"级，UI 中明确降级展示。

### 7.2 预测台账（协议）

```
theory 提出时，由用户在系统辅助下登记预测：
  断言（具体、可观察）+ 检验方式（检索可查 / 等待时间窗 / 回溯历史 session）+ 期限
    ↓
台账定期结算（手动触发或 session 启动时提醒）
    ↓
predictive_power = 命中数 / 已到期数        # 取代现在恒为 0.0 的占位
    ↓
连续 2 次落空 → 理论自动降级为"已削弱"，图中视觉淡化；用户可归档
```

MVP 阶段允许"回溯预测"（retrodiction）：用理论预测一个它未参与构建的历史 session 的图结构，命中即计分。这让台账在没有时间流逝时也能运转。

### 7.3 理论竞争（简化）

旧文档的"理论竞争"保留最小形式：同一现象集上覆盖重叠 > 50% 的两个理论构成竞争对，按 `predictive_power → 压缩值 → 复现 session 数` 字典序排名，仅影响展示顺序与推荐，不自动删除败者（多解释共存原则保留）。

## 八、删减清单

每一项删除都带理由。删除 ≠ 否定其美学价值，= 否定其当前的工程可行性或投入产出比。

| 旧设计 | 处置 | 理由 |
|--------|------|------|
| Cognitive Energy / Entropy / Attractor 动力学 | **删除** | 隐喻冒充数学：状态空间、测度、动力学方程均未定义且无人能定义。其想表达的"质量越来越好、越来越收敛"已由压缩值（5.1）+ 收敛判据（5.4）以可计算形式承接 |
| 多视角 Runtime（PerspectiveGraph、跨视角映射、视角竞争） | **降级为"视角透镜"** | 作为运行时结构，成本是图规模 × 视角数，且收敛机制未知——这就是它 20 个 Phase 都没被实现的原因。降级后的形式：expansion 的 prompt 层接受视角参数（经济学/心理学/制度视角），产出的变量带 perspective 标签进同一张图。视角对比作为展示功能而非认知架构 |
| Simulation 作为"动态世界模拟 / feedback loop rollout" | **收缩为现有职责** | 一致性检查 + 反事实删除分析是 simulation 实际能兑现的部分，保留并继续服务于压缩值计算。前向 rollout 推演在无真实动力学参数时只是 LLM 编故事，不做。feedback loop 需要图支持环，与现有 DAG 假设冲突，挂起至 H1/H2 通过后再议 |
| Attention Dynamics（attention 函数、迁移、约束） | **删除** | 其真实职责（下一步扩展什么）已由 reflection 引擎的规则优先级承担，且规则版可解释、可测试。一个没有定义的 attention 函数不比一个清晰的规则链高级 |
| Meta-Cognition（思考自己的思考） | **删除（承认已有实现即是它）** | reflection 引擎评估推理轨迹并决策，这就是 second-order cognition 的工程形式。不再保留一个暗示"还有更高层"的待办章节 |
| Memory Consolidation offline phase | **合并入 lexicon flush** | 现有 flush + 去重 + fitness 聚合就是 consolidation 的实现，不再维护一个更宏大的同义词 |
| "Self-Evolving Cognitive Civilization" 等远景 | **移入附录 A** | 不承诺、不排期、不影响决策 |
| 时间层（长期/短期/累积/触发） | **挂起** | 正确但非当前瓶颈。在证据接地（§六）稳定后，作为 evidence 字段的自然延伸（来源带时间戳）再评估 |

## 九、Roadmap 重排

原则：**验证假设的工作排在兑现假设的工作之前，兑现假设的工作排在打磨体验的工作之前。** 现有代码资产（四大引擎、TUI、Web 工作台、lexicon 双后端）全部保留，以下为增量方向。

### Phase V（验证，最高优先级，约 2-3 周）

1. 搭 H1 盲评实验：10 题、双组产出、5 人盲评。需要的开发量很小——主要是把现有产出整理成可对比的"叙事报告"形态（叙事层本就该是最后一步，现在补上）。
2. 在此期间**冻结**：Web 体验类迭代、移动端、导出、新 slash 命令。
3. H1 失败 → 回到 §〇，本文档作废重写；H1 通过 → 进入 Phase G。

### Phase G（接地，约 4-6 周）

1. 接地管线（6.1）：声明抽取 → 检索 → 判定 → evidence 落盘。复用 web_search.py。
2. 证据状态机（6.2）落入 schema 与前端（边样式按等级渲染、来源抽屉）。
3. 置信度公式切换到 5.3；压缩值与收敛判据切换到 5.1/5.4。
4. 跑 H2 实验。

### Phase T（理论可证伪，约 3-4 周）

1. 预测台账（7.2）：登记、结算、predictive_power 真实化。
2. 理论准入与降级（7.1、7.3）。
3. 持续测量 H3（复用率埋点已有数据基础）。

### Phase X（体验，仅在 V/G 通过后解冻）

按现有积压继续：HITL 异步化（兑现 §二 交互成本预算）、导出/分享、响应式。
