# Phase 17.2 Design — 问题分类 / light-model / session 删除 (3-feature combo)

**Date**: 2026-05-26
**Status**: design approved, ready for plan
**Trigger bug**: 用户问 "为什么易经中存在用九和用六的概念", bootstrap 生 13 现象全是西方科学 / 编程例子, **0 个易经内现象**.

## Root cause

`src/explain_engine/llm/prompts/variable_extraction.yaml` 现 system prompt 显式**禁止** "在 X 自己领域内列现象". LLM 完美执行 prompt — 适合 "为什么年轻人不消费" 这种现代社会因果, **不适合 "为什么 X 概念存在" 这种 domain-specific 解释类**.

修复设计哲学:
- 不同问题类型需要不同 "domain 配比" — 古典概念问题需要本域 ≥ 50%, 技术机制问题需要本域 ≥ 70%, 现代因果问题维持现 100% 跨域
- 引入前置 LLM call 做问题分类, 按 type 路由到不同 prompt
- 此前置 call 应该用 cheap model (haiku / gpt-4o-mini) 不该浪费 opus tokens
- 因此并入 Feature B (light-model 概念)
- 顺手补 Feature C (delete session) — 这是长期痛点, 一并 batch

## Feature A: Bootstrap quality fix (问题分类 + per-type prompt)

### Architecture

```
caller (chat / cli / bootstrap_phenomena 直接调用方)
   ↓
bootstrap_phenomena(question, llm, light_llm, ...)
   ↓
   type = await _classify_question(question, light_llm)
              ↳ fallback "causal_modern" on 任何错误
   ↓
   yaml_name = f"variable_extraction_{type}"
              ↳ causal_modern 对应 variable_extraction.yaml (物理保留, 不重命名)
              ↳ 其他 3 个走 variable_extraction_{type}.yaml
   ↓
   prompt = load_prompt(yaml_name)
   ↓
   ... 现 LLM call 流程不变 (prior_section / theories_section / structured output) ...
```

调用方零感知 — `bootstrap_phenomena` 内部完成 classify + prompt 选择.

### 4 个分类 + 各自 prompt 调性

| Type | 触发问题样例 | Prompt 调性 |
|---|---|---|
| `causal_modern` (default) | "为什么年轻人不消费" | 跨域优先 (5+ 领域, 禁同域分支) — 现 prompt 完全保留 |
| `concept_explanation` | "为什么易经里有用九用六" | **原 domain ≥ 50% (本域内 6-8 现象) + 跨域类比 ≤ 50%** |
| `mechanism` | "为什么 Raft 用 majority quorum" | **原 domain ≥ 70% (技术内现象) + 同类技术对比 ≤ 30%** |
| `phenomenon` | "为什么彩虹有 7 色" | **原 domain ≥ 40% (本域观察) + 跨域类比 ≤ 60%** |

### question_classify.yaml (light-model)

输入 question, 输出 `{"type": "causal_modern|concept_explanation|mechanism|phenomenon"}`. 走 light_llm, 提示词 ~500 token, 输出 ~50 token, 极快 + 极便宜.

System 提示要点:
- 解释 4 类的语义边界 + 提供典型问题样例 + 边界案例 (如何区分 mechanism vs causal_modern)
- 强制 JSON 输出, no preamble
- 明确 fallback: 若 unsure 或边界模糊, 选 `causal_modern` (默认行为退化)

### 替代方案 (落选)

- B: caller 自己 pass `question_type` — bootstrap 不做 classify. 缺点: chat / cli / direct caller 多处都要改, 易漏.
- C: classify 用 keyword 规则 (regex on "为什么 X 概念" / "为什么 X 不/会") — 古典 vs 现代边界模糊, 准确度低, 不可扩展.

### 文件改动

- `engines/bootstrap.py`: 新加 `_classify_question()` (async), `bootstrap_phenomena` 内插入 classify + per-type yaml load. 参数表加 `light_llm: LLMClient` (传 None = 不分类 = 走 causal_modern, backward compat).
- `llm/prompts/question_classify.yaml`: 新建.
- `llm/prompts/variable_extraction.yaml`: **物理保留不动** (= causal_modern alias).
- `llm/prompts/variable_extraction_concept_explanation.yaml`: 新建.
- `llm/prompts/variable_extraction_mechanism.yaml`: 新建.
- `llm/prompts/variable_extraction_phenomenon.yaml`: 新建.

### Error handling

- light_llm 自身 LLM 失败 → Feature B 的 `with_light_fallback` 自动切主 LLM
- classify 输出未知 type / parse 失败 → fallback `"causal_modern"`, log warning
- yaml 文件缺失 → raise FileNotFoundError (config 问题, 不该静默)

### Testing

- `test_classify_question.py`: 各分类 fixture LLM (mock light_llm.chat 返 type)
- `test_classify_fallback.py`: light_llm 失败 → 主 LLM 跑 classify (通过 `with_light_fallback`)
- `test_classify_unknown.py`: light 返垃圾 / 未列类别 → fallback "causal_modern" + log
- `test_variable_extraction_yaml_<type>.py` × 4: 各 yaml 结构验证 (system/user_template 字段齐全, json schema 描述正确)
- `test_bootstrap.py` (现存): light_llm=None → 跑 causal_modern → 等价现行为, 零回归.

## Feature B: light-model factory + 自动 fallback helper

### Architecture

```
config.py:
  make_light_llm_client() -> LLMClient
    读 LLM_LIGHT_* env, 缺则 fallback 主 LLM_*
    所有 LIGHT 全空 → 返主 LLM 实例 (= 无 light, 现行为 100% 一致)

llm/light_fallback.py (新):
  async def with_light_fallback(light_llm, main_llm, fn) -> result
    try:
      return await fn(light_llm)
    except (LLMError, SchemaValidationError) as exc:
      logger.warning("light_llm 失败, fallback 主 LLM: %s", exc)
      return await fn(main_llm)
```

> 注: LLM provider clients (`anthropic_protocol.py` / `openai_protocol.py`) 已 pre-wrap 所有 SDK 错 (Timeout/HTTPError/RateLimit/...) 为 `LLMError`, 故 helper 只需抓 `LLMError + SchemaValidationError` 即覆盖全部失败场景.

如果 light = main (同 client 实例), helper 跳 fallback (避免重复打).

### env vars

| Env | Fallback | 默认 / 推荐 |
|---|---|---|
| `LLM_LIGHT_PROTOCOL` | `LLM_PROTOCOL` | — |
| `LLM_LIGHT_BASE_URL` | `LLM_BASE_URL` | — |
| `LLM_LIGHT_API_KEY` | `LLM_API_KEY` | — |
| `LLM_LIGHT_MODEL` | `LLM_MODEL` | claude-haiku-4-5 / gpt-4o-mini |
| `LLM_LIGHT_MAX_TOKENS` | `LLM_MAX_TOKENS` (或写 4096) | 4096 (classify/signature 不要长输出) |

### 应用 scope

1. **Feature A 的 `_classify_question`** (新): light → fallback 主.
2. **lexicon 的 canonical mechanism** (现存): `_build_canonical_mechanism_cached` / `compute_canonical_signature` 内部 LLM call 用 `with_light_fallback` 包.

`LexiconBackend` (PG + JSON 两 backend) 构造接受 optional `light_llm` (默 None, None 时直接用主 llm, 跟现行为一致).

### 替代方案 (落选)

- B: caller 各自 try/except — 代码重复, classify / canonical 至少 2 处复制, 容易遗漏.
- C: `LightLLMClient` wrapper 类内部 fallback — 失去类型透明度, mock 麻烦, 不必要.

### 文件改动

- `config.py`: 新加 `make_light_llm_client()` (~30 行, 跟 make_llm_client 同款逻辑, 读 LLM_LIGHT_* 优先, 缺则读主 LLM_*).
- `llm/light_fallback.py`: 新建, `with_light_fallback()` 协程 (~25 行).
- `engines/lexicon.py`: `LexiconBackend.__init__` 加 optional `light_llm` 参数, canonical mechanism 包 with_light_fallback.
- `persistence/lexicon_pg.py`: 同上, 接受 light_llm 注入.
- `engines/bootstrap.py`: `bootstrap_phenomena` 参数表加 `light_llm: LLMClient | None = None`.
- `chat/session.py` / `cli.py`: 构造时调 `make_light_llm_client()` + pass down 到 bootstrap / lexicon.
- `.env.example`: 加 LLM_LIGHT_* 段.
- `README.md`: 加 light-model 段说明.

### Error handling

- light 失败 (任意被抓 exception) → log warning + fallback 主 LLM, 主 LLM 重试.
- 主 LLM 也挂 → 沿用现 raise (无新行为).
- light = main (同 client) → 跳 fallback 逻辑.

### Testing

- `test_make_light_llm_client_fallback_to_main.py`: LIGHT 全空 → 返跟 make_llm_client 一样的 client.
- `test_make_light_llm_client_independent.py`: LIGHT 全配 → 独立 client (不同 base_url / model).
- `test_with_light_fallback_success.py`: light 成功 → 不调主.
- `test_with_light_fallback_on_llm_error.py`: light raise LLMError → 调主 + log warning.
- `test_with_light_fallback_on_timeout.py`: light raise asyncio.TimeoutError → fallback.
- `test_with_light_fallback_skips_when_same_client.py`: light is main → 直接 fn(main), 不试 light.
- 集成: bootstrap_phenomena 用 light 跑 classify, mock light 失败 → 主 LLM 跑 classify.
- lexicon canonical signature 零回归 (light=None 默走主).

## Feature C: Session 删除

### Architecture

```
StorageV2.delete_session(sid)     ← rmtree session_dir (best-effort, 不存在 → FileNotFoundError; 中途挂留 partial dir)
        ↑
SessionStore.delete(sid)          ← thin wrapper
        ↑
   ┌────┴─────────┐
   │              │
cli delete   chat /delete
 typer.confirm    input(...) y/N
 + --force      + --force
```

### Behavior 细节

| 场景 | cli 行为 | slash 行为 |
|---|---|---|
| 不存在 sid | 红字报错 + exit 1 | err_failed("session 不存在") |
| 用户取消 (n) | 灰字 "已取消" + exit 0 | "已取消" |
| --force | 跳确认直删 | --force 标志同 cli (`"--force" in args`) |
| 当前活动 session | (cli 不会有此问题) | **拒绝**: "当前 session, 请先 /switch 或 /new 后再删" |
| 删成功 | 绿字 "已删 s_xxx" | slash_delete event ("已删 s_xxx") |

### 替代方案 (落选)

- B: 软删 (marker file) — 增 list_sessions 过滤复杂度, 无收益.
- C: 仅 cli 不加 slash — chat REPL 内体验断, 不愿.

### 文件改动

- `persistence/storage_v2.py`: 新加 `delete_session(sid: str) -> None` (~10 行, `shutil.rmtree(session_dir(sid))`, 不存在 raise FileNotFoundError).
- `persistence/session.py`: 新加 `SessionStore.delete(sid)` → `storage.delete_session`.
- `cli.py`: 新加 `@app.command("delete")` (~30 行, typer.confirm + --force).
- `chat/slash_commands.py`: 新加 `_handle_delete()` + register 到 `DEFAULT_COMMANDS`, slash arg parser 用简单 `"--force" in args`.
- `chat/chat_copy.py`: 新加 zh copy (STATUS_DELETE_CONFIRM / msg_delete_done / err_delete_active / err_delete_not_found).
- **不动 lexicon** (PG var.source_sessions 保留 dangling sid, 长期 var 跨 session 累积价值仍在).
- **不动 PG** (无 schema 变更).

### Error handling

- `shutil.rmtree` 失败 (e.g. 权限) → raise OSError, cli 报错 exit 1.
- 不存在 sid → FileNotFoundError → 友好 zh msg.
- 删自身 (chat REPL 当前 session) → 拒绝 slash, 提示先 /switch 或 /new.

### Testing

- `test_storage_v2_delete_session.py`: create + delete + verify dir gone.
- `test_storage_v2_delete_nonexistent.py`: FileNotFoundError.
- `test_session_store_delete.py`: thin wrapper.
- `test_cli_delete_with_confirm.py`: typer confirm input "y" / 取消 "n".
- `test_cli_delete_force.py`: --force 跳确认.
- `test_slash_delete.py`: /delete 流程.
- `test_slash_delete_current_session.py`: 拒绝删自身.
- `test_slash_delete_force.py`: --force 跳确认.
- `test_list_after_delete.py`: 删后 list_sessions 不含.
- 不破坏现 lexicon test (dangling sid 不挂查询).

## Implementation order (推荐)

按依赖顺序 batch:

1. **Feature B 先做** — `make_light_llm_client` + `with_light_fallback` helper.
   - 独立 module, 不依赖 A/C.
   - 现 lexicon canonical 改造 (light_llm 注入), test 零回归.
2. **Feature A 接上** — 用 light_llm 做 classify.
   - 依赖 Feature B 的 `with_light_fallback`.
   - 4 个 yaml + bootstrap 改造.
3. **Feature C 最后** (independent) — session delete.
   - 跟 A/B 无依赖, 可并行, 但放最后 batch 一起 commit 简单.

每 wave 内严格 red → green → commit, 中文 commit msg, 末尾 Co-Authored-By trailer.
