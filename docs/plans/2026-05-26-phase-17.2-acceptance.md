## Backward compat 说明

Phase 17.2 final review 反馈: 之前 "light_llm=None 时 100% Phase 17.1 行为" 措辞
不准. 准确描述需区分 **API 层 backward compat** 跟 **Production caller 行为变化**.

### API 层 backward compat (函数签名)

- `bootstrap_phenomena(question, llm)` (**不传** `light_llm`) — 跟 Phase 17.1
  byte-for-byte 一致: 跳 classify, 直接走 `variable_extraction.yaml` (= causal_modern,
  老 path). 现 9 个 `tests/test_engines_bootstrap.py` test 零修改.
- `_build_canonical_mechanism(node, session, llm)` (**不传** `light_llm`) — 跟
  Phase 17.1 一致: 直接走主 llm. light_llm 默 `None`.
- `flush_to_lexicon(session, storage, llm, llm_canonical_top_k)` (**不传**
  `light_llm`) — 跟 Phase 17.1 一致: 同步透 `light_llm=None` 给
  `_build_canonical_mechanism`, 零回归. light_llm 默 `None` (Phase 17.2 final
  review fix 后).

### Production caller 行为变化 (cli + chat)

`cli._run_new` / `cli._run_compress` / `cli` chat REPL / chat ephemeral
`promote_to_persistent` / chat slash `_handle_compress` 全部 **unconditionally**
构造 `light_llm = make_light_llm_client()` 并 pass 给 production 调点
(`bootstrap_phenomena` + `flush_to_lexicon`).

这意味着默用户**会**经历 1 次 classify LLM call (~1-6s, 走 cheap model;
`LLM_LIGHT_*` 未设时 fallback 主 LLM, 即 light=main 不同 instance 仍走 1 次 call).

这是 Feature A (bug fix) 的必需行为 — 不 classify 就不知道 phenomenon /
mechanism / concept_explanation 该走哪个 yaml. **design 的 backward compat 承诺
是 "API 层", 不是 "默用户行为完全等同 Phase 17.1"**.

### 不影响项

- **lexicon schema 不动**: PG `var.source_sessions` 删 session 时保留 dangling
  sid (设计决定, 见 design doc Feature C "不动 lexicon" 段).
- **PG schema 不动**: Phase 17.2 没动 schema, 没新 migration. Phase 17.1 PG 用户无影响.
- **`.env.example` 加 LLM_LIGHT_* 段全注释** — 老用户复制 .env 不变, 显式启用才用 light.
- **prompts/ 新 yaml 全部 NEW**: 老 `variable_extraction.yaml` 不动, 没 LLM_LIGHT_* +
  test 入口 (不传 light_llm) 仍走它.

### 已知 follow-up (列入 Phase 18)

caller 应检测 `LLM_LIGHT_*` env 全空 → light 跟 main 同 instance (避免 dual instance
开销) + 跳 classify 重复 LLM call (检测 light is main 时短路, 不调 classify, 直接
走默 yaml). 设计文档 "light is main" 段已注明, 留 Phase 18.

## 已知 follow-up (Phase 18 候选)

### I-2 — light client 多余 instance (Wave 2 review)

现状: `make_light_llm_client()` 即使 `LLM_LIGHT_*` env 全为空 (fallback 主 LLM_*), 也会构造一个新的 client instance, **跟主 client 不同 instance**. 浪费 ~ 2x token (light call 失败再 fallback main).

解决思路: caller 检测 `LLM_LIGHT_PROTOCOL/BASE_URL/MODEL` 都为空 → 复用 main client 同 instance (内部 `with_light_fallback` 检测 same instance 跳整个 fallback). 设计文档 (design.md "light is main" 段) 已注明.

留 Phase 18, 不在 17.2 scope.

### S-1 ~ S-5 — Wave 3 review polish (small)

- S-1: cli/slash err msg 加 hint (e.g. "session 不存在 — 可用 `explain list` 看现存 sid").
- S-2: `/help` 加 `/delete` 白名单, 让 `/help delete` 出帮助.
- S-3: `source_sessions` 保留 dangling sid 的注释加在 lexicon_pg.py 显眼处.
- S-4: design doc 加示例 sequence diagram.
- S-5: chat_copy zh 文案微调 (e.g. "已删 session" → "session XX 已删").

全是 polish, 不影响功能. 留 Phase 18 一起做.

### slash /delete 二次 confirm UX

现状: chat REPL 内 `/delete <sid>` **强制 --force** (没真二次 confirm). plan 当时简化, 因 chat handler 嵌 `input_provider` confirm 链路复杂.

future: chat REPL 实装 `input_provider` 后 (Phase 18+), 改为 `/delete <sid>` 默认走真二次 confirm (跟 cli `typer.confirm` 同体验), `--force` 跳 confirm.

### PG cross-test pool flakiness (preexisting)

`tests/test_lexicon_migrations.py::test_migrate_json_to_pg_basic` 在全量 pytest run 内偶现 fixture pool 冲突, 单文件跑全 PASS. 从 Phase 17.1 起就这样.

诊断方向: testcontainers PG pool / asyncpg connection lifecycle 跟其它 PG test fixture 顺序敏感. 不影响功能, 跟 Phase 17.2 完全无关. 留 Phase 18 (或更晚, 视严重程度).

### concept_explanation prompt 在 deepseek 上偶发 schema wrap

Smoke 1 跑 deepseek-v4-pro 时, BootstrapOutput 解析返回 `{input: {phenomena: [...]}}` 嵌一层 `input`, Pydantic 验证 fail. **跟 Phase 17.2 无关** — deepseek anthropic-compatible endpoint 对 schema 的 wrap habit (其它 prompt 也偶现). LLM 实际还是按 prompt 出了正确 phenomena, 12 条本域 ≥ 50% 都达成.

未来可在 `bootstrap_phenomena` 加 fallback unwrap (if `parsed` has `input` key → 提一层), 跟所有 endpoint 兼容. 不在 17.2 scope.
